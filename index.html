密度失控

05 多屏幕适配 状态在哪看 · 菜单跟谁走

多屏幕时菜单栏要回答两个问题：状态在哪看、菜单跟谁走。设计规则：应用菜单只属于主屏（焦点屏）；状态信息在所有屏幕同源可见；任何屏幕宽度不足时优先折叠，绝不挤压图标。

屏幕配置菜单栏行为
单屏完整菜单栏：应用菜单 + 五区状态，全量显示（基准形态）。
双屏（默认）主屏：应用菜单 + 五区；副屏：纯状态条，五区同源、无应用菜单。可在设置中为副屏开启应用菜单。
三屏及以上规则同双屏，所有副屏状态条内容一致；Dock 跟随指针所在屏幕（系统默认，设计不干预）。
竖屏副屏状态区右对齐不变；宽度不足时按「系统 → 时钟 → 通信 → 工具」顺序收缩，保留系统与时钟。
全屏应用该屏菜单栏自动隐藏，指针移至顶部临时呼出；其余屏幕完全不受影响。
远程会话（UU远程等）收敛为单一连接徽标：圆点表示连接质量（绿 / 琥珀 / 红），不堆叠多个图标。
不同分辨率与缩放图标与间距按 0.5× / 1× / 2× 缩放；栏高提供 24pt（紧凑）/ 28pt（宽松）两档。
刘海屏状态区整体避开刘海安全区，五区分区顺序与间距保持不变；亦可采用 Thaw 式「次级状态栏」双行方案。

07 设计原则 四条贯穿方案的规则

分区先于堆叠

按「系统 / 输入法 / 通信 / 工具 / 托盘」聚类，区间以 1pt 细线分隔。扫视成本随分区数量下降，而非图标数量上升。

默认克制，按需展开

工具区最多置顶 3 个；其余收入「+N」芯片，点击展开管理面板，支持一键置顶、还原与上限提示。

一套视觉语言

统一 16pt 模板图标、统一 20×20pt 命中区域、统一 8pt 区间距。菜单栏回归「状态」，而非应用广告牌。

状态即徽标

运行中 = 呼吸圆点，未读 = 数字徽标。用最小视觉面积传达最高频信息，避免整块彩色图标造成的噪音。

08 分区与优先级规范 可直接落地的结构定义
分区内容规则
系统区Wi-Fi、声音、电池P0 常驻，单色渲染；电池显示百分比，充电时绿色；点击展开合并面板
输入法区当前输入法（如「拼」）中文输入时高亮，英文输入时弱化；不占用独立图标
通信区有未读消息的应用数字徽标 ≤ 99；无未读时收入溢出区，不常驻
工具区AI / 开发工具最多 3 个置顶；运行中任务优先占位；其余进「+N」
托盘区聚焦搜索、控制中心、日期时间始终可见；时钟默认中文紧凑格式，可在设置切换
P0

常驻不可折叠：系统区、托盘区、时钟。任何密度与屏幕配置下都保持可见，保证基础状态随时可读。

P1

条件可见：输入法（中文输入时）、有未读的通信应用、正在运行任务的工具——出现即占据工具区空位。

P2

可折叠：其余第三方工具默认收入溢出区，用户可手动置顶（≤3 个），上限满时给出明确提示。

09 交互行为与技术映射 行为规格与实现路径

交互行为

  • 悬停 — 120ms 内显示圆角高亮底与名称/状态提示（仅支持 hover 的设备）。
  • 点击「+N」 — 180ms 展开管理面板，列出图标、名称、状态与置顶按钮。
  • 置顶 — 图标回到工具区；达到 3 个上限时提示先取消一个。
  • 键盘 — 全部交互可 Tab 触达，Enter/Space 触发，Esc 关闭面板，焦点在面板内圈定。
  • 徽标更新 — 数字变化时缩放反馈；运行圆点以 1.8s 周期呼吸。
  • 长按 / 右键 — 快速设置（亮度、音量、勿扰），与系统既有行为保持一致。

技术映射（macOS 原生）

  • NSStatusItem — variable length 布局，五区用固定间距分隔线实现。
  • SF Symbols — template 渲染模式，自动适配深/浅外观与高对比度。
  • 溢出管理 — NSMenu / NSPopover 承载折叠项，参考 Bartender / Ice 式交互范式。
  • 徽标 — NSStatusBarButton 子视图叠加，配合 NSWorkspace 通知更新状态。
  • 多屏幕 — 按 NSScreen 为每屏注册状态条；主从屏共享同一状态源，保证同源同步。
